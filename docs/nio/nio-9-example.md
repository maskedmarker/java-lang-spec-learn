# nio的使用


## kafka

```text
Kafka消息日志文件：
写路径：普通 write(顺序写,极快)
读路径：sendfile(零拷贝)

Kafka索引文件(稀疏索引)：
偏移量索引文件(.index): 将消息偏移量映射到物理文件位置
时间戳索引文件(.timeindex): 将时间戳映射到偏移量
索引文件很小适合全部加载到内存,高频访问不容易触发page-fault,这2个因素使得很适合使用mmap来映射索引文件.
由操作系统层面屏蔽了文件I/O的复杂性,这样操作索引文件起来就像是在操作内存数据.

kafka的高吞吐:
生产端批量发送
服务端顺序写入磁盘
消费端读取时,索引文件快速定位,sendfile快速发送.
多消费者时,topic分区,便于水平扩展.


Kafka把JVM变成“控制面”,把Linux内核变成“数据面”.
jvm层面用来决定从哪儿读写,实际的读写操作由kernel层面来完成.
```
